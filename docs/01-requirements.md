# 需求与验收

## 用户与目标

员工需要查询报销、差旅制度或产品 FAQ。用户输入问题，可附带对话历史。资料使用合成内容，每份文档有稳定的 ID 和版本日期。系统提供文档检索与片段读取工具，输出答案、引用的文档 ID 与原文片段、资料缺口和任务状态。

范围采用单 Agent、CLI 和本地资料。建议投入约三小时，优先完成真实模型的核心链路和可执行验证，复盘记录实际耗时与未完成项。

## 用例与通过标准

| 编号 | 条件与输入 | 通过标准 |
| --- | --- | --- |
| 01 明确答案 | 加载单条规则资料，问“报销期限多久？” | 查到并读取 D01，回答 30 天，引用 D01 原文。 |
| 02 文档冲突 | 用同一问题加载含 D01 和 D02 的资料，两篇分别写 30 天和 15 天，适用范围和优先级未说明 | 分别读取两篇，补充查证，引用两个期限并说明缺少什么，请用户确认适用制度。 |
| 03 资料外问题 | 问知识库未收录的政策 | 检索未找到足够证据时，说明资料缺口并返回 `out_of_scope`。 |
| 04 改写后的相似问题 | 在用例 01 的资料上问“垫付的钱最晚啥时候能报回来？” | 与直接问法得出相同结论，并保存初次召回不足、调整检索后命中的对照记录。 |
| 05 上下文追问 | 历史讨论出差住宿报销，本轮问“那最晚什么时候交？” | 根据上下文形成检索词，读取对应条款，引用支持答案的本轮原文。 |
| 06 工具失败 | 注入读取异常，且缺少其他可读证据 | 记录工具错误与模型后续动作，返回 `tool_error` 并说明缺少什么。 |
| 07 文档替换 | 固定用例 01 的问题，先替换 D01 的期限为 45 天，再对照用例 02 的冲突资料 | 期限替换使答案和引用同步变化。加入冲突使动作从读取后回答变成补充查证和追问。 |
| 08 执行上限 | 使用低预算，或在离线测试中安排持续检索 | 返回 `incomplete`，说明达到的上限，模型决策步数与工具调用次数均受控。 |

用例输入固定使用的资料和故障条件。用例 04 的对照记录包含检索词与命中文档 ID。用例 07 的对照记录包含资料版本、答案、引用和动作序列。人工复核引用是否支持答案里的数字、单位、对象和条件。

## 证据与交付

- `examples/` 至少包含三组输入、实际输出和运行记录，覆盖正常、信息或资料不足、工具失败，并覆盖六项必验。计划按用例分别保存，测试结果也放在此目录。
- 至少两条执行路径展示模型如何根据不同工具结果调整动作，优先保存用例 01 和 02 的真实模型 Trace。每条记录含步骤、工具参数、结果摘要、后续动作和简要可核对依据。Mock 只证明流程可运行。
- 同一仓库包含 `README.md`、`src/`、`tests/`、`examples/`、`data/`、依赖文件、`.env.example` 和下列五份文档。README 给出可复制的安装、运行与测试命令，代码和运行记录可直接复核。

| 文档 | 内容 |
| --- | --- |
| `01-requirements.md` | 用户、目标、范围、成功标准。 |
| `02-solution.md` | 调用流程、动态决策、技术取舍。若引入 Agent 框架，记录版本、使用的功能和承担的职责。 |
| `03-evaluation.md` | 预期、实际结果、失败、限制，逐项链接 `examples/` 下的证据。 |
| `04-ai-usage.md` | AI 辅助范围、个人贡献和修改、验证结果。 |
| `05-retrospective.md` | 最难问题、学习收获、下一步、实际耗时和未完成项。 |

最终提交第 3 题、GitHub URL 和最终 commit SHA。私有仓库需向指定评审账号开放读取权限。仓库只保存合成资料、脱敏记录和配置占位符。
